Pokémon Pokédex Analysis

Summary

I wanted to explore if it was possible to determine how strong a Pokemon was (their base_experience stat) based off their HP, attack, defense, and other stats, as well as based on their type. Beginning by first exploring the distribution for stats I viewed as most significant, base_experience and hp, we saw that there was a weak, positive association between the two, but not enough to suggest a definitive strong, positive trend. After this, I determined that considering more variables was necessary to get a more accurate prediction, rather than by just looking at their trend. To practice this, I fit a k-nearest neighbors model and a linear regression model on the data, both of which used all numeric predictors and the Pokemon’s type. My results showed that the linear regression model was better at predicting base_experience than our KNN model. From our results, we cannot conclusively say that we can predict base_experience from a Pokemon’s stats alone; we likely require a different method of modeling to see more accurate results.

Motivation and Context

I decided to investigate a dataset which contains the information for 949 different Pokemon, from the franchise by Nintendo. The information provided includes a Pokemon’s weight, height, as well as the different values for specific stats, like speed or attack. The Pokemon come from the first 7 generations of Pokemon, ranging from powerful and strong Pokemon like Mega-Evolutions and Legendaries, to basic and common Pokemon. These Pokemon, as mentioned, also have specific stat values related to the games/franchise, like speed or attack, but also type1, (a Pokemon’s “type” refers to the primary element that the Pokemon derives its power from, like water or fire). I decided to investigate this data set since I have been surrounded by self-described Pokemon-fanatics all my life, and so I felt most comfortable analyzing this data set.

Through this investigation, I wanted to explore if it is possible to predict a Pokemon’s base_experience stat, from their other stats, (attack, hp, type1, etc), for any Pokemon in our data set. I chose base_experience as a response value to predict, in order to essentially predict how “strong” or “powerful” a Pokemon is based off its other stats. I am expecting that stronger Pokemon (higher base_experience) are more likely to show higher values for their stats, than weaker Pokemon (lower base_experience). Regarding type, a categorical variable with over 15 classes, I would predict that types with smaller frequencies of Pokemon, would show a higher median base_experience stat than the others, given that they’re “rarer” and hence reserved for stronger Pokemon.

Data Description

As mentioned, the data set (here) I decided to investigate contains information on 949 different Pokemon, across 7 different generations, while also including different forms of the same Pokemon. Each observation in our data set corresponds to a Pokemon, and the 22 variables/columns in our data set correspond to a different stat being recorded; these range from height and weight, as well as other variables specific to Pokemon, like attack, speed, and their type. The data was collected by Internet users “williamorim” and “marcusmunch” on GitHub, with the information being taken from the Bulbagarden Wikipedia page for Pokemon.

Supervised Modeling

From our exploration, seeing as there is a weak association between base_experience and hp, I decided to fit a k-nearest neighbors model on our data set. These models would include the other variables in our data set, like attack, defense, etc, while making predictions for base_experience. This is significant seeing as there likely other variables necessary for accurately predicting base_experience.

I specifically went with a KNN model since I want to predict a numeric response, base_experience, and I presume that Pokemon with similar stats, would also have similar stats for base_experience, (going off my knowledge of Pokemon). The relationship also isn’t entirely linear, and KNN provides a simple model that can display nonlinear relationships. I also will be tuning the hyperparameter \(k\), which represents the number of neighbors we’ll be using in our KKN model.

K-nearest neighbors works by identifying \(k\) “neighbors”, or \(k\) closest data points to a given observation in our training data, and predicting its response value (base_experience in this case), based on the averages of base_experience from its neighbors. We want to avoid a small \(k\), since we might create too-simple of a model and begin overfitting, (low bias, but high variance due to neighbors’ averages will vary increasingly with smaller \(k\)s). We also want to avoid a large \(k\), otherwise we may underfit on our test set, (low variance, but high bias due to similar averages as \(k\) increases).

We begin by first setting up our cross validation for later, for when we tune \(k\).

set.seed(617, kind = "Mersenne-Twister")
poke.cv <- vfold_cv( # This will create a poke.cv for resampling later when we tune. 
  poke.train, # This argument is our training set. 
  v = 5 # This argument is the number of folds we'll be using. 
)

We’ll then create a model using k-nearest neighbors and add it to a workflow

poke.knn.model <- nearest_neighbor( # This creates a k-nearest neighbors model. 
  mode = "regression", 
  engine = "kknn",
  neighbors = tune(), # This is the parameter we're tuning, since we want to 
  # determine an optimal value for the number of neighbors.  
  dist_power = 1 # This argument refers to a parameter used in calculating the 
  # neighbors (Minkowki distance)
)

poke.knn.recipe <- recipe( # This creates the recipe for predicting 
  # base_experience based on the stats
  base_experience ~ type_1 + hp + attack + defense + special_attack + special_defense + speed,
  data = poke.train 
) |>
  step_zv() |>
  step_novel() |># These commands is necessary for an error later on
  step_dummy(all_nominal_predictors()) |> 
  step_normalize(all_numeric_predictors())  

poke.knn.wflow <- workflow() |> # We'll create our workflow and add the 
  # KNN model and recipe 
  add_model(poke.knn.model) |> 
  add_recipe(poke.knn.recipe)

Next we’ll set up the tuning grid to tune neighbors to find the best value for \(k\), based on the model’s RMSE, or residual mean squared error.

poke.tune.grid <- expand.grid( # This creates the grid of values that we'll 
  # use to tune k
  neighbors = seq(1, 50, by = 1)
)

poke.knn.tuned <- tune_grid( # This will actually take our workflow, and fit 
  # the KNN model (for each value of k in our tune grid), on each 
  # cross-validation fold, evaluating the RMSE for each fold
  poke.knn.wflow,
  resamples = poke.cv,
  grid = poke.tune.grid, 
  metrics = metric_set(rmse)
)

poke.knn.bestk <- select_best( # We'll select the best value for k 
  poke.knn.tuned)

Limitations and Future Work

From our models, despite tuning the number of neighbors, our KNN model poorly predicted base_experience in comparison to our linear regression model. It appears that a KNN model isn’t the best method for performing supervised learning on our data set. I presume this is the result of some collinearity between the variables, or grouping among the types of Pokemon. There is a possibility that certain types have higher averages for say, attack or speed, than others, which would affect the model’s predictions. In the future, I would suggest at looking at the data more intensively, and determining how and if we should include interaction terms in our workflows’ recipes, or also consider a Pokemon’s type2 stat, despite some having a missing value for this case.

From my experience here, I feel that the applications and methods that I applied to this data set could be applied to any real data set of living animals or organisms. Say, if given a data set which contained the biometric information of a large number of organisms for a specific species, the use of supervised learning and data exploration as I did here presents researchers with insights into their various health metrics, and also provides researchers with an avenue to go about determining the best method to predict said health metrics.
